# 仕様要約：よりみち日和

このファイルは、企画書・仕様書の内容を、実装者向けに要約したものです。

---

## アプリ概要

よりみち日和は、空き時間に何をするかを考える負担を減らし、短時間で実行できる小さな行動を提案する Web アプリケーションです。

ユーザーは以下の条件を選択します。

- 空き時間
- 強度
- 場所
- 予算

アプリは `activities.json` に登録された行動候補の中から条件に合うものを抽出し、ランダムに 1 件提案します。

---

## コンセプト

```text
空いた時間に、ちょっと新しい体験を。
```

予定と予定の間に生まれる隙間時間を、SNS や動画視聴だけで終わらせず、小さな行動の入り口に変えることを目指します。

---

## 対象ユーザー

主な対象は、授業・アルバイト・サークル活動の合間に 15〜60 分程度の空き時間が生じる大学生です。

想定する課題は以下です。

- 空き時間に何をするか考えるのが面倒
- SNS や動画視聴で時間が終わりやすい
- 新しいことをしたい気持ちはあるが、調べるほどの気力はない
- 短い空き時間では、検索や計画に時間を使いたくない

---

## MVP の範囲

MVP では、ログインや外部 API を使わず、ブラウザだけで動く構成にします。

### 必須機能

| 機能 | 内容 |
|---|---|
| 空き時間入力 | 15 分、30 分、45 分、60 分から選択する |
| 強度選択 | ゆるめ、普通、アクティブから選択する |
| 場所選択 | 学内、駅周辺、自宅、どこでもから選択する |
| 予算選択 | 0 円、500 円以内、指定なしから選択する |
| 行動提案 | 条件に合う行動候補を 1 件表示する |
| 再提案 | 条件を維持したまま別の候補を表示する |
| 実施記録 | 「やってみた」で履歴を保存する |
| スキップ記録 | 「スキップ」で未実施として保存する |
| 履歴表示 | 実施・スキップした行動を一覧表示する |

### 任意機能

| 機能 | 内容 |
|---|---|
| 実施率表示 | 実施回数 / 提案回数をパーセントで表示する |
| 条件緩和 | 候補がない場合に場所や強度の条件をゆるめる |
| 直近重複除外 | 直近に出た行動を再表示しにくくする |

## データ設計

## `activities.json`

行動候補を管理するファイルです。

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | string | 行動 ID |
| `title` | string | 行動タイトル |
| `description` | string | 行動説明 |
| `category` | string | カテゴリ |
| `min_minutes` | number | 最小所要時間 |
| `max_minutes` | number | 最大所要時間 |
| `intensity` | string | ゆるめ / 普通 / アクティブ |
| `location_type` | string | 学内 / 駅周辺 / 自宅 / どこでも |
| `budget_yen` | number | 必要予算 |
| `indoor` | boolean | 屋内行動か |
| `solo` | boolean | 1 人で可能か |
| `required_items` | string[] | 必要なもの |
| `weight` | number | 提案時の重み |

## `records`

実施・スキップ履歴です。MVP では `localStorage` に保存します。

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | string | 履歴 ID |
| `activity_id` | string | 提案された行動 ID |
| `activity_title` | string | 行動名 |
| `status` | string | `done` または `skipped` |
| `selected_minutes` | number | 選択した空き時間 |
| `selected_intensity` | string | 選択した強度 |
| `selected_location` | string | 選択した場所 |
| `created_at` | string | 記録日時 |

## `condition`

ユーザーが入力した条件です。

| フィールド | 型 | 説明 |
|---|---|---|
| `free_minutes` | number | 空き時間 |
| `intensity` | string | 希望する強度 |
| `location_type` | string | 現在の場所 |
| `budget_yen` | number または 指定なし | 許容予算 |

---

## 提案ロジック

基本条件は以下です。

| 条件 | 判定 |
|---|---|
| 所要時間 | `activity.max_minutes <= condition.free_minutes` |
| 強度 | `activity.intensity === condition.intensity` |
| 場所 | `activity.location_type === condition.location_type` または `どこでも` |
| 予算 | `activity.budget_yen <= condition.budget_yen`。ただし指定なしの場合は無視 |

処理の流れ：

1. ユーザーが条件を選ぶ
2. `activities.json` から条件に合う行動を抽出する
3. 直近に出た行動を除外する
4. 候補がある場合、ランダムに 1 件選ぶ
5. 候補がない場合、条件を一部ゆるめて再検索する
6. 提案画面に表示する

---

## 保存方式

MVP では、以下のように保存します。

| データ | 保存先 |
|---|---|
| 行動候補 | `src/data/activities.json` |
| 実施履歴 | `localStorage` |
| ユーザー認証情報 | 保存しない |
| Google Calendar の予定情報 | 取得しない |
| 位置情報 | 取得しない |

## 実装上の注意

- MVP では外部 API を使わない
- MVP では個人情報を扱わない
- Google Calendar の予定タイトル・説明文・参加者情報は保存しない方針にする
- 失敗時に利用意欲が下がらないよう、連続日数よりも実施率を重視する
- まずは「条件入力」「行動提案」「履歴保存」を完成させる
