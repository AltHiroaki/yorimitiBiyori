# 仕様要約：よりみち日和

このファイルは、`よりみち日和` の現在の仕様を実装者向けに要約したものです。

---

## アプリ概要

よりみち日和は、ユーザーが登録した興味カテゴリをもとに、短い空き時間でできる行動やコンテンツを提案する iOS / Android 向け Flutter アプリです。

ユーザーは最初に自分の興味カテゴリを登録します。

例：

- 音楽
- YouTube
- 読書
- 散歩
- 学習
- 映画
- 料理
- ゲーム

その後、通知やアプリ内操作から空き時間を選ぶと、登録した興味と選択時間に合う提案をランダムに表示します。

---

## コンセプト

```text
空いた時間に、興味の中からちょっと新しい体験を。
```

「寄り道」を、物理的な移動だけでなく、興味の範囲を少し広げる行動として捉えます。

例：

- 普段聴かない音楽を1曲だけ聴く
- 気になる分野の新しい YouTube チャンネルを探す
- 短い記事を1本読む
- テーマを決めて散歩する
- 気になる分野を少し調べる

---

## 対象ユーザー

主な対象は、空き時間を毎回 SNS や動画視聴だけで終えてしまいがちな大学生です。

想定する課題は以下です。

- 空き時間に何をするか考えるのが面倒
- 興味はあるが、自分から調べるほどの気力はない
- いつも同じコンテンツや行動に偏りがち
- 短い空き時間では、検索や計画に時間を使いたくない
- 新しいことをしたいが、始めるきっかけがない

---

## MVP の範囲

MVP では、ログインや外部 API を使わず、端末内で完結する構成にします。

### 必須機能

| 機能 | 内容 |
|---|---|
| 興味カテゴリ登録 | ユーザーが興味のあるカテゴリを選択・保存する |
| 通知時刻設定 | 通知を受け取りたい時間帯を設定する |
| ローカル通知 | 設定時刻に通知を表示する |
| 通知アクション | 通知上で 15分 / 30分 / 60分 を選べるようにする |
| 提案表示 | 選択時間と興味カテゴリに合う提案を1件表示する |
| 再提案 | 条件を維持したまま別の候補を表示する |
| 実施記録 | 「やってみる」で履歴を保存する |
| スキップ記録 | 「スキップ」で未実施として保存する |
| 履歴表示 | 実施・スキップした提案を一覧表示する |
| 設定画面 | 興味カテゴリ、通知設定、履歴削除を扱う |

### 任意機能

| 機能 | 内容 |
|---|---|
| 実施率表示 | 実施回数 / 提案回数をパーセントで表示する |
| 直近重複除外 | 直近に出た提案を再表示しにくくする |
| アプリ内時間選択 | 通知ではなくアプリ内から 15分 / 30分 / 45分 / 60分 を選べるようにする |

## 画面仕様

表示するもの：

- 履歴画面への導線
- 設定画面への導線

## 提案画面

条件に合う提案を 1 件表示する画面です。

表示するもの：

- 提案タイトル
- 所要時間
- カテゴリ
- 説明文
- やってみるボタン
- 別の提案ボタン
- スキップボタン

通知アクションから開いた場合は、通知で選択された時間を条件として使います。

## 履歴画面

実施・スキップした提案を振り返る画面です。

表示するもの：

- 実施回数
- スキップ回数
- 実施率
- 履歴一覧
- 表示フィルター

## 設定画面

通知と興味カテゴリを管理する画面です。

表示するもの：

- 興味カテゴリ設定
- 通知時刻設定
- 通知許可の説明
- 履歴削除
- アプリ説明
- バージョン情報
- プライバシーに関する説明

## データ設計

## `assets/data/suggestions.json`

提案候補を管理するファイルです。

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | string | 提案 ID |
| `title` | string | 提案タイトル |
| `description` | string | 提案説明 |
| `category` | string | 表示用カテゴリ |
| `interest_tags` | string[] | どの興味カテゴリに合うか |
| `duration_minutes` | number | 所要時間 |

## `records`

実施・スキップ履歴です。MVP では端末内保存を使います。

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | string | 履歴 ID |
| `suggestion_id` | string | 提案 ID |
| `suggestion_title` | string | 提案名 |
| `status` | string | `done` または `skipped` |
| `selected_minutes` | number | 選択した空き時間 |
| `created_at` | string | 記録日時 |

## `user_settings`

ユーザー設定です。

| フィールド | 型 | 説明 |
|---|---|---|
| `interest_tags` | string[] | ユーザーが登録した興味カテゴリ |
| `notification_enabled` | boolean | 通知を使うか |
| `notification_time` | string | 通知時刻 |

---

## 提案ロジック

基本条件は以下です。

| 条件 | 判定 |
|---|---|
| 所要時間 | `suggestion.duration_minutes <= selected_minutes` |
| 興味 | `suggestion.interest_tags` がユーザーの興味カテゴリと1つ以上一致する |

処理の流れ：

1. ユーザーが興味カテゴリを登録する
2. 通知またはアプリ内操作で空き時間を選ぶ
3. `suggestions.json` から条件に合う提案を抽出する
4. 直近に出た提案を必要に応じて除外する
5. 候補がある場合、ランダムに 1 件選ぶ
6. 候補がない場合、時間条件のみで再検索するか、興味カテゴリの再設定を促す
7. 提案画面に表示する

---

## 保存方式

MVP では、以下のように保存します。

| データ | 保存先 |
|---|---|
| 提案候補 | `assets/data/suggestions.json` |
| 興味カテゴリ | 端末内保存 |
| 通知設定 | 端末内保存 |
| 実施履歴 | 端末内保存 |
| ユーザー認証情報 | 保存しない |
| 外部サービス情報 | 取得しない |

## 実装上の注意

- MVP では外部 API を使わない
- MVP ではログインを使わない
- MVP では個人情報を扱わない
- 通知機能は Android / iOS で挙動差があるため、実機確認を行う
- まずは「興味登録」「時間選択」「提案表示」「履歴保存」を完成させる
