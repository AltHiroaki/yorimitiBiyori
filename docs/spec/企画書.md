# 企画書：よりみち日和

> このファイルは、提出版 PDF「企画書 ver5」の内容をリポジトリ向けに整理したものです。デザイン・設計の正本は提出版 PDF です。実装は [仕様書](./仕様書.md) を参照してください。

## 1. 概要

コンセプトコピー：**「好きなことで、いつもと違う角度から。」**

よりみち日和は、興味カテゴリ（音楽・料理・読書・映画・散歩など）を選び、続けて簡単な詳細設定で好みを絞り込むと、その中から「いつもとは違うもの」を詳細情報つきでランダムに提案するネイティブアプリである。好きなことを続けながら、いつもと少し違う角度で楽しむきっかけを作る。

- コンセプト：好きなことはそのまま続けていい。ただ、たまにはちょっと違う角度で。
- 位置づけ：手はあるがディープではない人に、好きな領域の中での偶然的な新しい出会いを届ける。

## 2. 背景と課題

**背景①：好きなことがあるからこそ、アプリを使い始める。**
新しいアプリを使い始めるのは「何も持っていない人」ではなく「関心・意欲がある人」である。ふだん音楽を聴き、たまに手を出すという程度から、「いつもと同じだな、たまには違うものも試したいな」という気持ちは生まれる。よりみち日和は、ディープな知識はなくても好きなことを持つ人を対象とする。

**背景②：好きなことの中でもマンネリは起こる。**
好きでも、固定化した行動パターンから抜け出すきっかけがない。

解決すべき課題（表1）：

| 課題 | 詳細 |
|---|---|
| 体験の固定化 | 好きでもいつも同じものを選んでしまう。固定化した行動パターンから抜け出すきっかけがない |
| 「新しいもの」への踏み出しコスト | 違うものも試したいが、何を選べばいいかわからない。調べて選ぶ工程が面倒で結局同じになる |
| 詳細情報がないと試せない | 「ボサノバを」「タジンを」と言われても、どんなものかわからないと試す気になれない |

## 3. ターゲットとペルソナ

主要ターゲットは、興味はあるがディープまではいかない**ライト層**である。マニア層は自力で深掘りできるためアプリの浅い提案では物足りず、逆に詳細情報の伴わない浅い提案ではライト層も動けない。「カテゴリ選択後の詳細設定」という二段階により、ライト層にとってちょうどよい粒度の提案を届ける。MVP はログイン不要で Android に対応する。

ペルソナ例：音楽好きの大学生（普段から音楽をよく聴く／カフェで流れるような作業用 BGM がほしい）、料理好きの会社員（たまに自炊するが献立がほぼ同じ／簡単に作れるアジア風の一品を 500 円以内で試したい）など。

## 4. 具体的な提案例（二段階方式）

カテゴリを選んだあとに簡単な詳細設定で好みを絞り込む**二段階方式**を採用する。これにより「浅く広い」提案ではなく、ライト層にとってちょうどよい具体性を持った提案を実現する。

カテゴリ別の詳細設定の例（表3）：

| カテゴリ | 詳細設定の選択肢（例） |
|---|---|
| 音楽 | 気分：作業向け / リラックス / 盛り上がりたい　ジャンル：ポップス / ジャズ / クラシック / 洋楽　費用：有料 / 無料 / 問わない |
| 料理 | 栄養・ダイエット：高タンパク / 低糖質 / 野菜多め / カロリーオフ　ジャンル：和食 / 洋食 / 中華 / イタリアン / アジアン / 丼 / 作り置き / ガッツリ |
| 読書 | ジャンル：エッセイ / 小説 / ノンフィクション / 詩集　読書時間：10分以内 / 30分 / じっくり　入手・予算：図書館 / 電子書籍 / 〜500円 / 〜1000円 |
| 映画 | 気分：泣ける / 笑える / 考えさせる　上映時間：90分以内 / 問わない　視聴先：Netflix / Amazon Prime / 問わない |

絞り込んだ条件に合う提案が、内容・入手先などの詳細情報つきで届く（表4）：

| カテゴリ | 提案される内容例 | 詳細情報の例 |
|---|---|---|
| 音楽 | カフェで流れるようなジャズ、作業用 BGM、洋楽ポップス | 「歌詞がなく集中しやすい。勉強や作業の BGM にぴったり。配信サービスのプレイリストですぐ聴ける」 |
| 料理 | ガパオライス、麻婆豆腐、トマトリゾットなど | 「炊飯器で作れて簡単。いつもの食材でアジア風の味に。材料費 500 円以内」 |
| 読書 | 話題のエッセイ、短編集、写真の多い旅行本など | 「1 話 10 分で読める。電車の中でも気軽に。普段読まない人でも読みやすい」 |
| 映画 | 話題のアニメ映画、笑えるコメディ、泣ける感動作など | 「90 分前後で見やすい。Netflix で視聴可能。休日に気軽に楽しめる」 |

> 散歩カテゴリは仕様書で補完（目的：気分転換 / 運動 / 発見、時間：15分以内 / 30分 / たっぷり）。難易度・移動距離は扱わない。

## 5. 課題と解決の対応

- 体験の固定化 → 好きな領域の中でランダムに「いつもとは違うもの」が届く。固定化した選択から外れる。
- 踏み出しコスト → 詳細設定でライト層にちょうどよい具体性に絞る。何を選べばよいか迷わない。
- 詳細情報がないと試せない → 提案カードに内容・入手先・予算を添える。発展では Claude API で毎回違う説明を生成し、「これなら試そう」と判断できる状態にする。

## 6. 既存サービスとの差別化

差別化の核心：**「好きな領域の中で、知らなかった自分の好みと出会える」**。

| 比較項目 | Serendipity Planner | Reclaim.ai | よりみち日和 |
|---|---|---|---|
| 対象領域 | 外出スポット中心 | タスク・予定管理 | 音楽・料理・読書・映画など趣味全般 |
| 提案の絞り込み | 場所・時間 | スケジュール最適化 | カテゴリ＋詳細設定の二段階 |
| 行動の事前登録 | 不要 | 必要 | 不要（DB から自動抽出） |
| 詳細情報の量 | 場所情報のみ | × | 内容・入手先・予算あり |
| ランダム性 | あり | ランダム性少 | カテゴリ内でランダム |
| 対象ユーザー | 外出好き | 予定重視の人 | 趣味のライト層 |

## 7. UI・UX 画面紹介

Flutter で実装するプロトタイプ画面を作成した。ボトムナビゲーションによる「提案」「履歴」「設定」の 3 画面構成、Material 3 のグリーン基調 UI で構成する。

- 提案画面：カテゴリと詳細設定で絞り込んだ提案を 1 件カード表示。「やってみる」で実施、「別の提案」で再提案。
- 履歴画面：実施・スキップ・合計時間の集計を表示。最近の履歴をアイコン付きでリスト表示。
- 設定画面：興味カテゴリ・詳細設定の初期値・履歴管理をここで行える。通知時刻も設定する。

各画面はボトムナビゲーションで切り替える。提案画面でカテゴリと詳細設定を選び、ランダムに届く提案を実施・スキップして履歴に記録される。

## 8. 機能詳細・サービス仕様

サービスの処理フロー（初期実装版 MVP）：

| 入力 | 処理 | 出力 |
|---|---|---|
| カテゴリ選択（音楽 / 料理 / 読書 / 映画など）→ 詳細設定で好みを絞り込み（ジャンル・予算など） | suggestions.json を読み込み → 条件に合う候補を抽出 → 直近重複を除外 → 重み付きランダムで 1 件選択 | 提案カード（タイトル・詳細説明・入手先・予算）→ やってみる / 別の提案 / スキップ → shared_preferences に記録 |

**行動カタログの設計**：行動候補は `assets/data/suggestions.json` で管理し、各カテゴリごとに候補を登録する。`id`・`title`・`description`・`detail`・`category`・`tags`（詳細設定に対応）・`budget_yen`・`where_to_try`・`estimated_minutes`・`weight` のフィールドで構成する。詳細設定の選択はタグでフィルタリングし、直近 3 件を除外してランダムサンプリングする。発展版では Claude API で `detail` を動的生成する。

> 注：提出版 PDF では `difficulty`（難易度）フィールドを挙げているが、本プロジェクトでは**難易度は撤廃**した。

## 9. 実装方針

開発初心者が多いため、認証・外部 API・DB・バックエンドを最初から全部入れると複雑になりすぎる。授業内で完成させる最小構成（MVP）を先に固め、余裕ができた段階で発展機能を追加する。中心機能「**カテゴリ選択 → 詳細設定 → 提案 → 履歴保存**」をまず安定させる方針とする。

MVP 技術構成（表7）：

| 分類 | 使用技術 | 用途 |
|---|---|---|
| アプリフレームワーク | Flutter | Android で開発する |
| 言語 | Dart | Flutter アプリの実装に使う |
| UI | Material 3 | スマホ向けの画面・ボタン・ナビゲーションを構築する |
| 画面遷移 | Flutter 標準 / 将来的に go_router | 提案・履歴・設定画面を切り替える |
| 状態管理 | StatefulWidget（必要に応じて Riverpod） | MVP では複雑化を避ける |
| 提案データ | assets/data/suggestions.json | 提案候補を JSON で管理する |
| 履歴・設定保存 | shared_preferences | ログインなしで端末内に保存する |
| テスト | flutter_test | ロジック・Widget のテストを行う |

**MVP に含めない機能**：ユーザーログイン・Google Calendar API・Firebase Authentication・Firestore・Google Maps/Places API・位置情報取得・YouTube API・音楽サービス連携・AI API のリアルタイム生成。いずれも MVP 完成後の発展機能として検討する。

**実装順序**：まず Flutter プロジェクトの起動確認と 3 画面（提案・履歴・設定）の骨格、カテゴリ選択と詳細設定の UI、および suggestions.json の提案データを整備する。次にタグによるフィルタリングとランダム提案ロジックを実装する。最後に実施・スキップ記録の保存処理を実装し、iOS 確認環境が確保できた段階で実機確認を行う。

## 10. 発展機能・まとめ

MVP 完成後、AI API による説明生成、Firebase Authentication、Cloud Firestore、YouTube・音楽サービス連携、Google Calendar 連携、位置情報・周辺スポット提案を段階的に検討する。AI 提案は呼び出しのたびに生成するのではなく、まとめて生成・保存し候補からランダムに選ぶ方針とする。

論点：好きなことで、いつもと違う角度から。知らなかった自分の好みと出会いの瞬間を作る。
