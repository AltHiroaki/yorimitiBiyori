# 要件定義：よりみち日和 Flutter版

このファイルは、現在のFlutter版よりみち日和で満たす要件を整理するためのものです。

仕様の正本は企画書（2026年6月10日提出版）と `よりみち日和 UIプロトタイプ/` です。詳細な画面・データ仕様は [仕様要約](./仕様要約.md) を参照してください。

旧Web版の要件は `archive/old-web-version/docs/requirements.md` に移動しました。

## 1. プロジェクト概要

よりみち日和は、ユーザーが登録した興味カテゴリと、時間・予算・移動距離の条件をもとに、空き時間でできる小さな「よりみち」を提案するAndroid向けアプリである。MVPではAndroidのみを対象とし、iOS対応はMVP完成後の発展版で導入する。

ユーザーが自分で検索して行動を決めるのではなく、アプリが通知やアプリ内操作をきっかけに提案を出す。日常の空き時間に、いつもと少し違う選択肢を差し込むことを目的とする。

## 2. 想定ユーザー

- 空き時間をSNSや動画視聴だけで終えがちな大学生・社会人
- 気分転換したいが、何をするか考えるのが面倒な人
- 興味はあるが、自分から調べるほどの気力はない人
- 短い時間で試せる行動のきっかけがほしい人

## 3. 解決したい課題

空き時間があっても、何をするかを考えるには手間がかかる。その結果、いつも同じアプリやコンテンツに流れやすい。

よりみち日和は、興味カテゴリと空き時間・予算・移動距離に合う提案を短く出すことで、迷う時間を減らし、小さな行動を始めやすくする。

## 4. MVPの提供価値

- 興味カテゴリと条件（時間・予算・移動距離）をもとに提案を受け取れる
- 5分、15分、30分、60分の空き時間に合わせて提案を選べる
- 通知をきっかけに使えるため、アプリを自分から探しに行かなくてよい
- 実施やスキップを記録し、フィードバック付きであとから振り返れる
- ログインなしで端末内に保存できる

## 5. 機能要件

### 5.1 オンボーディング

初回起動時に、初回起動モーダル → 興味カテゴリ選択 → 通知許可モーダルの3ステップを表示する。

通知許可を「あとで」にしても、手動提案だけで利用できる。

### 5.2 興味カテゴリ登録

ユーザーはオンボーディングまたは設定画面で、興味のあるカテゴリを複数選択できる。

カテゴリは、散歩、音楽、読書、学習、カフェ、写真、整理、休憩、運動、買い物の10種とする。

### 5.3 提案条件の設定

ユーザーは提案設定画面で、以下の条件を設定・保存できる。

- 使える時間：5分 / 15分 / 30分 / 60分
- 予算：0円 / 500円以内 / 1000円以内 / 指定なし
- 移動距離：その場でできる / 徒歩5分以内 / 徒歩15分以内 / 少し遠くてもよい

難易度の選択UIは設けない。行動の重さは時間の選択で表現する。

### 5.4 時間選択（通知アクション）

通知上では15分、30分、60分の3つから時間を選べる。通知で選んだ時間は一時条件として使い、保存済みの提案設定は書き換えない。

### 5.5 提案表示

アプリは、条件（時間・予算・移動距離・興味カテゴリ）に合う提案を1件表示する。

提案カードには、タイトル、説明文、タグ、所要時間を表示する。提案画面の上部には現在の提案条件カードを表示する。

### 5.6 再提案

ユーザーは「別の提案」で同じ条件のまま別の候補を表示できる。このとき表示中だった提案はスキップとして記録する。

### 5.7 実施記録とフィードバック

「やってみる」を押すと完了モーダルが表示され、「よかった / 普通 / 合わなかった」の3択でフィードバックを選び、実施済みとして履歴に保存できる。

### 5.8 履歴表示

ユーザーは過去に実施またはスキップした提案を一覧で確認できる。

履歴画面には、実施数、スキップ数、合計時間（分）を表示する。履歴が0件のときは空状態と提案画面への導線を表示する。

### 5.9 履歴削除

設定画面から端末内の履歴を削除できる。削除前に確認を表示し、取り消せないことを明示する。

### 5.10 通知

ユーザーは通知時刻（デフォルト17:30）と通知のON/OFFを設定できる。

設定時刻になるとローカル通知を表示し、通知本文のタップで提案画面を開き、通知アクションで15分、30分、60分の時間を選べるようにする。

発展版では、固定時刻だけでなく通知時間帯を設定し、その範囲内で毎日ランダムな時刻に通知する方式を検討する。MVPでは固定時刻通知を優先する。

## 6. 非機能要件

- スマートフォンで読みやすく、押しやすいUIにする（Material 3、グリーン基調）
- 提案表示までの待ち時間を短くする
- 端末内保存の読み書きに失敗しても画面が壊れないようにする
- MVPでは通知の挙動をAndroid EmulatorとAndroid実機で確認する
- MVPではログインや外部APIを使わず、個人情報の扱いを最小限にする

## 7. MVPでやらないこと

- ユーザーログイン・Googleアカウント連携（設定画面に「未連携」の行として表示するのは可）
- Google Calendar連携
- Firebase連携
- Google MapsやPlaces APIの利用
- 位置情報を使った提案
- YouTube APIや音楽サービス連携
- AI API（Claude API）によるリアルタイム生成
- 通知時間帯のランダム化
- クラウド保存やアカウント同期
- iOS版の生成、ビルド、通知確認

これらはMVP完成後の発展機能として扱う。

## 8. 成功条件

- 初回起動時にオンボーディングで興味カテゴリを登録できる
- 提案設定で時間・予算・移動距離を変更できる
- 条件に合う提案が1件表示され、「別の提案」で再抽選できる
- 「やってみる」からフィードバック付きで実施記録を保存できる
- 履歴画面で実施数・スキップ数・合計時間と記録一覧を確認できる
- 通知から時間を選び、提案画面に移動できる
- 設定画面から履歴を削除できる
