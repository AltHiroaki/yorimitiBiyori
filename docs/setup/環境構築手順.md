## 1. このファイルの目的

このファイルは、**よりみち日和を Flutter アプリとして自分の PC で動かせる状態にするまでの手順**をまとめたものです。

現在の `よりみち日和` は、Web アプリではなく Flutter アプリとして開発します。MVP では Android のみを対象にし、iOS は発展版で導入します。

---

## 2. よりみち日和の初期実装方針

MVP では以下の方針で作ります。

- Flutter で Android アプリとして作る
- MVP の実装・検証対象は Android のみにする
- iOS は MVP 完成後の発展版で導入する
- ログイン機能は入れない
- Google Calendar API は最初から入れない
- Firebase / Firestore は最初から入れない
- YouTube API や音楽サービス連携は最初から入れない
- AI API は最初から入れない
- 提案データは `assets/data/suggestions/<category>.json` でカテゴリ別に管理する
- 実施履歴や設定は端末内に保存する
- 通知から 15分 / 30分 / 60分 を選び、提案画面を表示する

まずは **「興味登録 → 通知 → 時間選択 → 提案 → 履歴保存」** という中心機能を完成させます。

## 7. Flutter SDK を入れる

本リポジトリは Flutter 3.44 以上（Dart 3.12 以上）を前提にしています。CI は Flutter 3.44.2 で検証しています。導入後に `flutter --version` で確認してください。

公式サイト：

```text
https://docs.flutter.dev/get-started/install
```

公式サイトは情報量が多いため、Windows + VS Code で進める場合は、まず以下の手順だけ確認すれば十分です。

### Windows + VS Code で入れる最短手順

1. VS Code を開く
2. `Ctrl + Shift + P` でコマンドパレットを開く
3. `flutter` と入力する
4. `Flutter: New Project` を選ぶ
5. Flutter SDK の場所を聞かれたら `Download SDK` を選ぶ
6. Flutter SDK の保存先を選ぶ
7. `Clone Flutter` を押す
8. ダウンロード後に `Add SDK to PATH` を押す
9. VS Code とターミナルを閉じて開き直す

Flutter SDK の保存先は、Windows では以下がおすすめです。

```text
C:\src\flutter
```

または以下でも問題ありません。

```text
C:\dev\flutter
```

以下の場所は避けます。

```text
C:\Program Files
C:\Program Files (x86)
C:\Windows
C:\Users\<ユーザー名>\OneDrive\...
C:\Users\<ユーザー名>\Desktop\...
```

`Program Files` は管理者権限や空白入りパスでつまずきやすく、OneDrive や Desktop は同期・移動・削除の影響を受けやすいためです。

インストール後、ターミナルで確認します。

```bash
flutter --version
```

Flutter の環境診断は以下です。

```bash
flutter doctor
```

`flutter doctor` は、Flutter 開発に必要なツールが揃っているか確認するコマンドです。

### `flutter` が見つからない場合

以下のようなエラーが出る場合は、Flutter SDK の `bin` フォルダが PATH に入っていない可能性があります。

```text
flutter : 用語 'flutter' は、コマンドレット、関数、スクリプト ファイル、または操作可能なプログラムの名前として認識されません。
```

まず、Flutter SDK が実際にあるか確認します。

```powershell
Test-Path C:\src\flutter\bin\flutter.bat
```

`True` と出る場合は、Flutter 本体はあります。直接指定すれば動くか確認できます。

```powershell
& 'C:\src\flutter\bin\flutter.bat' --version
```

その後、Windows の環境変数 `Path` に以下を追加します。

```text
C:\src\flutter\bin
```

追加後は、VS Code とターミナルを閉じて開き直します。再起動後、以下が通れば OK です。

```powershell
flutter --version
flutter doctor
```

## 8. Android Studio と Android Emulator

Android Studio 公式サイト：

```text
https://developer.android.com/studio
```

Android Studio を入れる理由：

- Android SDK を管理する
- Android Emulator を作る
- Android のビルドに必要なツールを入れる

Android Emulator の作成手順：

1. Android Studio を開く
2. Device Manager を開く
3. Create Device を選ぶ
4. Pixel 系の端末を選ぶ
5. Android の system image を選ぶ
6. Emulator を起動する

起動中の端末確認：

```bash
flutter devices
```

アプリ起動：

```bash
flutter run
```

## 9. Xcode と iOS Simulator

iOS を確認するには macOS と Xcode が必要です。MVP では iOS を対象にしないため、この章は発展版で iOS を導入するときに参照します。

Xcode：

```text
https://developer.apple.com/xcode/
```

Xcode を入れた後、必要に応じて以下を実行します。

```bash
sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -runFirstLaunch
```

iOS Simulator の起動は Xcode から行うか、Flutter から起動できます。

```bash
open -a Simulator
flutter devices
flutter run
```

## 11. Flutter の platform ディレクトリを生成する

このリポジトリでは、`android/` と `ios/` は Flutter SDK で生成する前提にしています。MVP では `android/` のみを生成します。

```bash
flutter create --platforms=android .
```

すでに `lib/` や `pubspec.yaml` がある状態で実行しても、Flutter の不足している platform ファイルを補えます。

実行後、以下のようなディレクトリが作成されます。

```text
android/
```

発展版で iOS を導入する段階になったら、以下を実行して `ios/` を追加生成します。

```bash
flutter create --platforms=ios .
```

## 14. 解析とテスト

コード解析：

```bash
flutter analyze
```

テスト：

```bash
flutter test
```

MVP では、まず以下をテスト対象にします。

- 選択時間以内の提案だけ出るか
- 興味カテゴリに合う提案だけ出るか
- 履歴の実施数・スキップ数を正しく数えられるか

通知機能は OS 依存があるため、自動テストだけでなく実機確認も必要です。

---

## 15. 通知機能の確認方針

通知は段階的に確認します。

```text
1. アプリ内でカテゴリ＋詳細設定を選んで提案できる
2. ローカル通知が表示される（文言は時間を名指ししない）
3. 通知をタップするとアプリが開く
4. 保存済みのカテゴリ＋詳細設定で提案画面に遷移する
```

最終的には以下で確認するのが望ましいです。

- Android 実機

iOS は発展版で導入するため、その段階で iPhone 実機確認を行います。

---

## 16. よくある確認先

| 状況 | 確認すること |
|---|---|
| `flutter` コマンドが見つからない | Flutter SDK の PATH 設定 |
| `flutter doctor` でエラーが出る | Android Studio / SDK の設定。iOS 導入時は Xcode も確認 |
| Android Emulator が出ない | Android Studio の Device Manager |
| iOS Simulator が使えない | macOS かどうか、Xcode が入っているか |
| `flutter pub get` で失敗する | `pubspec.yaml` のインデント、ネットワーク |
| アプリが起動しない | `flutter devices`、エラーメッセージ |
| 通知が出ない | 通知許可、OS 設定、実機確認 |
