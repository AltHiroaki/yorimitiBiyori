# 仕様要約：よりみち日和

このファイルは、`よりみち日和` の現在の仕様を実装者向けに要約したものです。

仕様の正本は **企画書（2026年6月10日提出版）** と **`よりみち日和 UIプロトタイプ/`（Figma 書き出し）** です。
両者が食い違う場合は、画面構成・UI 文言・操作フローはプロトタイプを、データ設計・処理フロー・発展方針は企画書を優先します。

---

## アプリ概要

よりみち日和は、ユーザーが登録した興味カテゴリと、時間・予算・移動距離の条件をもとに、空き時間でできる小さな「よりみち」を 1 件提案する Android 向け Flutter アプリです。MVP では Android のみを対象にし、iOS 対応は MVP 完成後の発展版で導入します。

- 企画コンセプトコピー（企画書）：「好きなことで、いつもと違う角度から。」
- アプリ内タグライン（プロトタイプ）：「空いた時間に、小さなよりみちを。」

---

## 提案条件

提案は以下の 4 条件で絞り込みます。**難易度の選択 UI は設けません**。企画書の設計方針どおり、行動の重さは時間の選択で表現します。

| 条件 | 選択肢 | 備考 |
|---|---|---|
| 使える時間 | 5分 / 15分 / 30分 / 60分 | 通知アクションは 15 / 30 / 60 の 3 つ。5分はアプリ内のみ |
| 予算 | 0円 / 500円以内 / 1000円以内 / 指定なし | |
| 移動距離 | その場でできる / 徒歩5分以内 / 徒歩15分以内 / 少し遠くてもよい | |
| 興味カテゴリ | 下記 10 種から複数選択 | |

初期値（プロトタイプの DEFAULT_CONDITIONS）：15分・500円以内・徒歩15分以内・カテゴリ［散歩、カフェ、読書］

### 興味カテゴリ（10 種）

| id | 表示名 | 絵文字 |
|---|---|---|
| walk | 散歩 | 🚶 |
| music | 音楽 | 🎵 |
| read | 読書 | 📖 |
| learn | 学習 | 💡 |
| cafe | カフェ | ☕ |
| photo | 写真 | 📷 |
| tidy | 整理 | 🗂️ |
| rest | 休憩 | 🌿 |
| exercise | 運動 | 🏃 |
| shop | 買い物 | 🛍️ |

注：プロトタイプのオンボーディング画面（06）には「買い物」を除く 9 種が表示されていますが、提案設定画面（04）は 10 種です。実装はこの 10 種をマスターとして両画面で共通に使います。
企画書 04 章の「料理」「映画」はカテゴリ追加の候補として発展版で検討します。

## 画面構成

ボトムナビゲーション 3 タブ構成です。**ホーム画面はありません**（提案タブがトップ画面）。

| # | 画面 | 役割 |
|---|---|---|
| 01 | 提案（タブ1） | 現在の提案条件カードと「今日のよりみち」カードを表示する |
| 02 | 履歴（タブ2） | 実施・スキップの集計と履歴一覧を表示する |
| 03 | 設定（タブ3） | 提案設定・興味カテゴリ・通知・履歴削除を管理する |
| 04 | 提案設定（サブ画面） | 時間・予算・移動距離・カテゴリを編集する |
| 05 | 初回起動モーダル | オンボーディング 1/3 |
| 06 | 興味カテゴリ選択 | オンボーディング 2/3 |
| 07 | 通知許可モーダル | オンボーディング 3/3 |
| 08 | 通知カード | OS の通知（参考デザイン） |
| 09 | 提案完了モーダル | 「やってみる」後のフィードバック入力 |
| 10 | 履歴空状態 | 履歴 0 件のときの表示 |

### 01 提案画面

- ヘッダー：アプリ名「よりみち日和」＋タグライン「空いた時間に、小さなよりみちを。」
- **現在の提案条件カード**：
  - ピル表示：⏱ 時間 / ¥ 予算 / 📍 移動距離 ＋ 選択カテゴリ名の列挙
  - 右上に「提案設定 >」テキストボタン → 提案設定画面へ遷移
  - 通知から開いた場合はオレンジのバッジ「通知から選択: ◯◯分」を表示し、時間条件を一時的に上書きする
- **今日のよりみちカード**：
  - ラベル「今日のよりみち」＋「◯◯分でできる」
  - 提案タイトル（大見出し）、説明文、タグチップ＋時間チップ
  - ボタン 2 つ：「やってみる」（FilledButton）／「別の提案」（OutlinedButton）
- 案内カード：「通知をタップすると選んだ時間の提案が表示されます。条件を変えたいときは「提案設定」から調整できます。」

### 02 履歴画面

- サマリーカード（3 分割）：**実施数 / スキップ数 / 合計時間（分）**
  - 合計時間は実施（done）レコードの分数合計
- 「最近の履歴」リスト：ステータスアイコン（✓ 緑＝実施、− 黄＝スキップ）、タイトル、日付、タグ・所要時間、実施/スキップバッジ
- 0 件のときは空状態（10）：「まだ履歴はありません」＋「提案を見てみる」ボタン（提案タブへ）

注：旧仕様にあった実施率表示・フィルターはプロトタイプに含まれないため、MVP では任意機能とします。

### 03 設定画面

- 見出し：「興味カテゴリ、通知時刻、アカウント、履歴を管理します。」
- **基本設定**カード：
  - Google アカウント（未連携 / 連携ボタン）… **発展版**。MVP では表示のみ・未連携固定でもよい
  - 提案設定（時間・予算・移動距離を調整）→ 提案設定画面へ
  - 興味カテゴリ（選択中カテゴリを列挙）→ 編集
  - 通知時刻（例：毎日 17:30）→ 変更
  - 通知トグル（空き時間のきっかけを受け取る）
- **データ**カード：
  - 履歴削除（赤字）。タップでインライン確認「本当に削除しますか？この操作は取り消せません。」＋キャンセル / 削除する
  - アプリについて（よりみち日和 MVP）
- 注記：「MVPではログインなしでも利用できます。Googleアカウント連携は、バックアップや将来のカレンダー連携に使います。」

### 04 提案設定画面

AppBar 付きサブ画面（戻るボタンあり）。提案画面の「提案設定」または設定画面から遷移します。

1. 使える時間：FilterChip（5分 / 15分 / 30分 / 60分、単一選択）
2. 予算：2×2 グリッドの ChoiceChip（0円 / 500円以内 / 1000円以内 / 指定なし）
3. 移動距離：ラジオ行（その場でできる / 徒歩5分以内 / 徒歩15分以内 / 少し遠くてもよい）
4. 興味カテゴリ：FilterChip 複数選択（10 種、絵文字付き）＋「◯つ選択中」

下部固定：「この条件で保存」（FilledButton）／「初期設定に戻す」（TextButton）

### 05–07 オンボーディング

初回起動時のみ表示します。上部に 3 ステップのプログレスインジケーター。

1. **初回起動モーダル**：「よりみち日和へようこそ」＋説明＋「はじめる」
2. **興味カテゴリ選択**：「興味のあるよりみちを選んでください」。FilterChip 複数選択。0 件のときは「次へ」を無効化
3. **通知許可モーダル**：「よりみちのきっかけを通知します」。「通知を許可する」／「あとで」。**拒否しても手動提案だけで利用できる**

### 08 通知

- 設定した通知時刻（デフォルト 17:30）にローカル通知を毎日表示する
- 通知文言例：「15分だけ、少し歩いてみませんか？」「30分の空き時間、ありませんか？」
- 通知本文をタップ → **提案画面**を開く
- 通知アクション：15分 / 30分 / 60分。選んだ時間は一時条件として提案画面に渡す（保存済みの提案設定は書き換えない）

### 09 提案完了モーダル

「やってみる」を押すと ModalBottomSheet を表示します。

- 「おつかれさまです」「今回のよりみちはどうでしたか？」
- ChoiceChip 3 択：😊 よかった / 🙂 普通 / 😐 合わなかった
- 「履歴に保存」→ status = done ＋フィードバックを記録

---

## 操作と記録

| 操作 | 動作 |
|---|---|
| やってみる | 完了モーダルを表示 → フィードバック選択 → `status = done` で履歴に保存 |
| 別の提案 | 表示中の提案を `status = skipped` として記録し、同条件で再抽選して次を表示 |

注：企画書の処理フローには「やってみた / 別の提案 / スキップ」の 3 操作がありますが、プロトタイプの提案カードはボタン 2 つです。本仕様では「別の提案」を押した時点で表示中の提案をスキップ記録とすることで両者を統合しています（要チーム確認の設計判断）。

## データ設計

### `assets/data/suggestions.json`

企画書 08「行動カタログの設計」のフィールド構成に従います。初期リリース時点で **50 件以上**登録します。

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | string | 提案 ID。安定した一意な値 |
| `title` | string | 提案タイトル（カードの大見出し） |
| `description` | string | カードに表示する短い説明文 |
| `detail` | string | 詳細説明。発展版では Claude API で動的生成する対象 |
| `category` | string | 主カテゴリ。10 種のカテゴリ表示名のいずれか |
| `tags` | string[] | カードに表示するタグ。カテゴリ照合にも使う |
| `min_minutes` | number | 実施に最低限必要な分数 |
| `max_minutes` | number | かかっても収まる目安の分数 |
| `intensity` | string | `light` / `normal` / `active`。MVP ではフィルタに使わない予約フィールド |
| `location_type` | string | `spot`（その場）/ `walk5` / `walk15` / `far` |
| `budget_yen` | number | 費用目安。無料は 0 |
| `where_to_try` | string | 入手先・場所・始め方のヒント |
| `weight` | number | 重み付きランダム選択の重み |

### `records`（実施・スキップ履歴）

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | string | 履歴 ID |
| `suggestion_id` | string | 提案 ID |
| `suggestion_title` | string | 提案タイトル |
| `category` | string | カテゴリ |
| `selected_minutes` | number | 選択していた時間 |
| `status` | string | `done` または `skipped` |
| `feedback` | string \| null | `good` / `normal` / `bad`。skipped のときは null |
| `created_at` | string | 記録日時。ISO8601 |

### `user_settings`

| フィールド | 型 | 説明 |
|---|---|---|
| `selected_categories` | string[] | 選択中の興味カテゴリ id |
| `selected_minutes` | number | 使える時間（5 / 15 / 30 / 60） |
| `budget_option` | string | `free` / `under500` / `under1000` / `unlimited` |
| `distance_option` | string | `spot` / `walk5` / `walk15` / `far` |
| `notification_enabled` | boolean | 通知 ON/OFF |
| `notification_time` | string | 通知時刻。デフォルト `17:30` |
| `first_launch_completed` | boolean | オンボーディング完了フラグ |
| `recent_suggestion_ids` | string[] | 直近重複除外用。直近 3 件 |

## 提案ロジック

企画書 表 5「サービスの処理フロー」に従います。

| 条件 | 判定 |
|---|---|
| 時間 | `suggestion.min_minutes <= selected_minutes` |
| 予算 | `suggestion.budget_yen <=` 予算上限（指定なしは制限なし） |
| 移動距離 | `suggestion.location_type` が選択範囲内（spot ⊂ walk5 ⊂ walk15 ⊂ far の包含順） |
| カテゴリ | `suggestion.category` または `tags` が `selected_categories` の表示名と 1 つ以上一致 |
| 直近重複 | `recent_suggestion_ids`（直近 3 件）に含まれる提案は除外 |
| 選択 | 候補から `weight` を考慮してランダムに 1 件選ぶ |

処理の流れ：

1. オンボーディングで興味カテゴリを登録する
2. 提案設定（または通知アクションの一時条件）で時間・予算・移動距離が決まる
3. `suggestions.json` を読み込む
4. 上記条件で候補を抽出し、直近 3 件を除外する
5. 候補があれば weight 付きランダムで 1 件選び、提案画面に表示する。表示した ID を `recent_suggestion_ids` に追加する
6. 候補がなければ、直近除外を一時解除して再検索する（同一提案の連続表示は避ける）
7. それでも候補がなければ、条件の変更（時間を延ばす・カテゴリを増やす）を促すメッセージを表示する
8. JSON 読み込みに失敗したら「データの読み込みに失敗しました。再起動してください。」と表示する

## 保存方式

| データ | 保存先 |
|---|---|
| 提案候補 | `assets/data/suggestions.json`（アプリ同梱） |
| ユーザー設定（条件・カテゴリ・通知） | shared_preferences |
| 実施・スキップ履歴 | shared_preferences（JSON 文字列） |
| ユーザー認証情報 | 保存しない（MVP） |
| 位置情報・カレンダー情報 | 取得しない（MVP） |

## 発展機能

MVP 完成後に、以下を検討します。

### 発展 Phase 1

- 提案候補の増加（各カテゴリ 20 件以上）、カテゴリ追加（料理・映画など）
- **Claude API による `detail` フィールドの動的生成**（企画書 08。カテゴリ・提案タイトル・所要時間を渡して生成する。API キーはアプリ内に置かず Cloud Functions 側で管理する）
- 実施率表示・履歴フィルター

### 発展 Phase 2

- iOS 版の platform ファイル生成、ビルド、実機確認
- iOS の通知許可、ローカル通知、通知アクション対応

### 発展 Phase 3

- Firebase Authentication（Google アカウント連携。設定画面の「連携」を有効化）
- Cloud Firestore による履歴・設定のクラウド保存（バックアップ）
- Cloud Functions for Firebase（AI API を安全に呼ぶ）

### 将来構想

- Google Calendar 連携、予定間の空き時間自動検出
- 位置情報を使った周辺スポット提案
- YouTube API・音楽サービス連携

AI 提案を導入する場合も、通知時に毎回 AI を呼ぶのではなく、提案候補をまとめて生成して保存し、通知時は保存済み候補からランダムに表示します。

## 実装上の注意

- MVP では外部 API・ログイン・個人情報を扱わない
- 通知権限を拒否されても手動提案だけで利用できるようにする
- 通知の挙動は Android Emulator と Android 実機で確認する（iOS は発展版）
- まずは「オンボーディング」「提案表示」「履歴保存」をアプリ内で完結させ、通知は最後に組み込む
- UI プロトタイプ（React）はデザイン参照専用。React のコードや依存を Flutter 実装に持ち込まない
