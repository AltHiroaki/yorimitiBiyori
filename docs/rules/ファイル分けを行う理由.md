# ファイル分けを行う理由：Flutter版

このドキュメントは、よりみち日和のFlutter版でファイルを分ける理由と、主な置き場所を説明するためのものです。

旧Web版のファイル分け説明は `archive-reference-materials` ブランチの `archive/old-web-version/docs/file-separation-guide.md` にあります。

## 1. ファイル分けの目的

ファイル分けは、見た目をきれいにするためだけの作業ではありません。

実装が進んだあとに、どこを直せばよいか分かりやすくし、変更の影響範囲を小さくするために行います。

よりみち日和では、画面、提案データ、提案ロジック、履歴保存、共通UIを分けて扱います。

## 2. 現在の基本構成

```text
yorimichiBiyori/
├─ lib/
│  ├─ main.dart
│  └─ src/
│     ├─ app/
│     ├─ pages/
│     └─ widgets/
├─ assets/
│  └─ data/
│     └─ suggestions/
│        ├─ music.json
│        ├─ cook.json
│        ├─ read.json
│        ├─ movie.json
│        └─ walk.json
└─ docs/
```

今後、機能が増えたら以下のフォルダを追加します。

```text
lib/src/features/
lib/src/models/
lib/src/repositories/
```

## 3. 主な置き場所

| 場所 | 役割 |
|---|---|
| `lib/main.dart` | アプリの起動点 |
| `lib/src/app/` | アプリ全体の設定、ルートWidget、ナビゲーション |
| `lib/src/pages/` | ホーム、提案、履歴、設定などの画面 |
| `lib/src/widgets/` | 複数画面で使う共通Widget |
| `lib/src/features/` | 興味登録、提案、通知、履歴など機能ごとの処理 |
| `lib/src/models/` | 提案、設定、履歴などのDartモデル |
| `lib/src/repositories/` | JSON読み込み、端末内保存などのデータアクセス |
| `assets/data/` | 静的な提案データ |
| `docs/` | 現在の仕様、計画、開発ルール |
| `archive-reference-materials` ブランチ | 旧Web版と UI プロトタイプの保管場所（main には置かない） |

## 4. 画面Widgetに詰め込みすぎない

ページWidgetには、画面の構成と操作の受け取りを書きます。

次の処理が大きくなってきたら、別ファイルに分けます。

- 提案JSONの読み込み
- 提案候補の絞り込み
- ランダム選択
- 実施率の計算
- 端末内保存の読み書き
- 通知アクションIDの解析

画面は表示に集中し、計算や保存は別の場所に置くと、あとから変更しやすくなります。

## 5. 具体例

提案画面そのものは、以下に置きます。

```text
lib/src/pages/suggestion_page.dart
```

提案データの型は、以下のように分けます。

```text
lib/src/models/suggestion.dart
```

提案を選ぶ処理は、以下のように機能単位で分けます。

```text
lib/src/features/recommendation/
```

履歴の保存や読み込みは、以下に置きます。

```text
lib/src/repositories/
```

## 6. 分けすぎにも注意する

まだ数行しかない処理を無理に細かく分けると、逆に追いにくくなります。

最初は読みやすい場所に素直に書き、処理が大きくなったら分けます。

判断に迷ったときは、次の順で考えます。

1. 画面表示なら `pages`
2. 複数画面で使うUIなら `widgets`
3. データ構造なら `models`
4. 保存や読み込みなら `repositories`
5. 機能固有の処理なら `features`

## 7. 旧Web版を分けた理由

以前のReact / TypeScript版の `src/` がルートに残っていると、Flutter版の `lib/src/` と混ざって見えます。

現在の作業対象を分かりやすくするため、旧Web版は main から外し、`archive-reference-materials` ブランチへ退避しました。

今後の実装では、基本的に `lib/`、`assets/`、`docs/` を見ます。
