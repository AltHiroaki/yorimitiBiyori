日付は入れていません。日付が決まったら、各マイルストーンに締切を追記してください。

## 進行順序

```text
M0 → M1 → M2 → M4 → M5
        ↘ M3 ↗
```

- `M1 → M2 → M4` の順は変えない（提案が動かないと履歴も通知も意味がないため）

## M0：基盤（残タスクのみ）

### M0 残タスク：チーム環境で動作確認する

```md
## 作業内容
チームの各メンバーの環境で `flutter pub get` → `flutter analyze` → `flutter test` を実行し、結果を確認する。

## 目的
誰の環境でも同じ状態でビルド・テストできることを M1 着手前に保証するため。

## やること
- [ ] `flutter pub get` を実行する
- [ ] `flutter analyze` を実行し、警告・エラーを記録する
- [ ] `flutter test` を実行し、失敗があれば記録する
- [ ] 落ちた場合は内容を Issue にコメントし、対応する

## 完了条件
- [ ] 全員の環境で `flutter analyze` がクリーンに通る
- [ ] 全員の環境で `flutter test` が通る
```

- 対象領域：`setup` ／ 優先度：`high`（M1 着手のブロッカー）

## M1：提案が動く

依存：なし（最初に着手する）

### 1-1 モデル定義

```md
## 概要
`Suggestion` / `UserSettings` / `SuggestionRecord` / 興味カテゴリ定数のモデルクラスを定義する。

## なぜ必要か
提案データ・設定・履歴を型安全に扱うため。Map や dynamic を画面に直接渡すと、フィールド名の誤りや null 処理でバグが起きやすい。

## やること
- [ ] `lib/src/models/suggestion.dart`：`Suggestion`。`fromJson` は欠損フィールドで例外にせず、その 1 件をスキップする
- [ ] `lib/src/models/user_settings.dart`：`UserSettings`（カテゴリ・カテゴリ別詳細設定 `detail_settings`・通知設定・直近提案ID）。デフォルト値を持つ
- [ ] `lib/src/models/suggestion_record.dart`：`SuggestionRecord`（`estimated_minutes` 含む）。`status`（done/skipped）と `feedback`（good/normal/bad/null）は enum にする
- [ ] `lib/src/models/interest_category.dart`：MVP 4 カテゴリの定数（id・表示名・絵文字）＋カテゴリ別の詳細設定グループ定義（MVP は「ジャンル」1 グループ）。散歩は `developmentCategories` として定義を残す。仕様書 3.4 の表を正とする

## 完了条件
- [ ] 各モデルの fromJson/toJson 往復テストが通る
- [ ] 壊れた JSON を渡してもクラッシュしない
```

- 対象領域：`data` ／ 優先度：`high`

### 1-2 データ読み込みと提案ロジック

```md
## 概要
suggestions.json の読み込みと、条件に合う提案を選ぶ純粋関数群を実装する。

## なぜ必要か
提案ロジックを UI から分離し、単体テストで固めることで、画面側の変更に強くする。

## やること
- [ ] `lib/src/repositories/suggestion_repository.dart`：`rootBundle` から suggestions.json を読み、`List<Suggestion>` を返す。パース失敗は呼び出し側に伝える
- [ ] `lib/src/features/recommendation/suggestion_picker.dart` を純粋関数で実装：
  - [ ] `filterSuggestions`：カテゴリ一致＋カテゴリ別詳細設定（タグ）のフィルタ（仕様書 6.1）
  - [ ] `pickWeightedRandom`：`Random` を引数で受け取りテスト可能にする
  - [ ] `excludeRecent`：直近 3 件除外。候補が尽きたら直前 1 件のみ除外に緩和（仕様書 6.3）

## 完了条件
- [ ] 仕様書 10.1 の単体テスト（カテゴリ・詳細設定タグ・予算・直近除外・重み・履歴集計）がすべて通る
```

- 対象領域：`recommendation` ／ 優先度：`high` ／ 依存：1-1

### 1-3 設定の保存

```md
## 概要
`UserSettings` を `shared_preferences` で保存・読込する repository を実装する。

## なぜ必要か
MVP ではログインを使わないため、設定は端末内に保存する必要がある。

## やること
- [ ] `shared_preferences` を pubspec に追加する
- [ ] `lib/src/repositories/settings_repository.dart`：キー `yorimichi_biyori_settings` で保存・読込する
- [ ] 読込失敗時はデフォルト値に安全フォールバックする

## 完了条件
- [ ] 保存 → アプリ再起動 → 設定が復元される
```

- 対象領域：`settings` ／ 優先度：`high` ／ 依存：1-1

### 1-4 提案設定画面

```md
## 概要
カテゴリ選択とカテゴリ別詳細設定を編集する提案設定画面を二段階で実装する。

## なぜ必要か

## やること
- [ ] `lib/src/pages/suggestion_settings_page.dart` を作成する
- [ ] 第1段階：カテゴリの FilterChip 複数選択を実装する
- [ ] 第2段階：選択カテゴリごとに詳細設定グループ（FilterChip 複数選択）を表示する
- [ ] 「この条件で保存」「初期設定に戻す」ボタンを実装する

## 完了条件
- [ ] 保存 → アプリ再起動 → 設定が復元される

- 対象領域：`settings` ／ 優先度：`high` ／ 依存：1-1, 1-3（1-1/1-2 完了前はモック値で進めてよい）

### 1-5 提案画面の本実装

条件カードと「今日のよりみち」カードを表示する提案画面を本実装する。

- [ ] 今日のよりみちカード（タイトル・description・タグ・入手先・予算）
- [ ] 「別の提案」で再抽選する

## 完了条件

```

- 対象領域：`suggest` ／ 優先度：`high` ／ 依存：1-1, 1-2（1-1/1-2 完了前はモック値で進めてよい）

**M1 完了の目安**：エミュレータで「条件を変える → 条件に合う提案が出る」をデモできる。

## M4：通知（Android）

依存：M1〜M2 完了後

### 4-1 通知基盤

```md
## 概要
flutter_local_notifications を使い、毎日決まった時刻に通知を出す基盤を実装する。

## なぜ必要か
通知が、空き時間に提案を届ける入口になるため。

## やること
- [ ] `flutter_local_notifications` を pubspec に追加する
- [ ] `lib/src/features/notifications/notification_service.dart`：初期化、権限リクエスト、毎日 `notification_time` にスケジュール、ON/OFF でキャンセル
- [ ] 通知を 1 件表示できる（文言は時間を名指ししない柔らかい誘い。例「暇な時間って存在しますか？」）
- [ ] 本文タップでアプリが開き提案画面になる（保存済みのカテゴリ＋詳細設定で提案）
- [ ] 時間を選ぶ通知アクション（15/30/60分）は設けない

## 完了条件
- [ ] 通知をタップして提案画面が開き、保存条件で提案される
- [ ] 通知文言に分数が含まれない
```

- 対象領域：`ui`（通知専用の選択肢がないため代用）／ 優先度：`high`
