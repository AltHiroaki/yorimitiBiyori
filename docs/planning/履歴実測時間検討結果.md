# 履歴実測時間の検討結果

最終更新：2026年7月28日

関連Issue：

- 検討：[Issue #134](https://github.com/AltHiroaki/yorimitiBiyori/issues/134)
- 実装：[Issue #156](https://github.com/AltHiroaki/yorimitiBiyori/issues/156)
- 中断機能の検討：[Issue #137](https://github.com/AltHiroaki/yorimitiBiyori/issues/137)

## 結論

完了したよりみちには開始時刻と終了時刻を保存し、履歴の表示と合計時間には、信頼できる実測所要時間を優先して使う。

寝落ち、完了忘れ、端末時刻の変更などで実測値が異常になった場合は、そのレコードに保存済みの `estimated_minutes` へフォールバックする。履歴では採用した値の根拠を `実測 N分` または `目安 N分` と表示する。

完了時の時間確認・編集は追加しない。実装、既存仕様書の更新、テスト追加は Feature Issue #156 で行う。#156 が完了するまでは、現在の履歴が実測時間を表示・集計するものとして扱わない。

## 現行実装の確認

- `OngoingSuggestion` は `suggestionId` と `startedAt` を保存している
- 実施中状態は shared_preferences に保存され、タブ切替やアプリ再起動後も復元される
- スキップ履歴から復活した場合は、復活時に新しい開始時刻を設定している
- `SuggestionRecord` は `estimatedMinutes` と `createdAt` を持つが、開始・終了時刻は持たない
- `record_summary.dart` は done レコードの `estimatedMinutes` を合計している
- records の保存形式にはversion 1が設定され、versionなしの旧形式も読める

開始時刻の取得と永続化は既にできているため、完了操作時に終了時刻を確定し、履歴へ引き継ぐことで実測できる。

## 決定事項

| 論点 | 決定 |
|---|---|
| 実測時間を導入するか | 導入する |
| 保存する値 | done レコードに nullable な `started_at` / `completed_at` を追加する |
| skipped レコード | 開始・終了時刻を持たず、提案の目安時間だけを表示する |
| 終了時刻 | 完了ボタンでモーダルを開く直前に確定する |
| 異常値 | 決定した上限を超える場合は `estimated_minutes` へフォールバックする |
| 日付跨ぎ | 日付が変わったことだけでは異常値にしない |
| 履歴一覧 | 採用値を `実測 N分` または `目安 N分` と表示する |
| 目安値との併記 | 同じ履歴行に2つの時間は並べない |
| 既存レコード | `目安 N分` として維持し、合計にも含める |
| 完了時の確認・編集 | 採用しない |
| 中断時間 | 現時点では除外しない。中断機能を採用するときに拡張する |

## 実測値の採用条件

開始時刻から終了時刻までの経過時間が、次のすべてを満たす場合に実測値を採用する。

1. done レコードである
2. 開始・終了時刻が両方とも有効である
3. 終了時刻が開始時刻より後である
4. 経過時間が実測採用上限以内である

実測採用上限は次の式で求める。

```text
実測採用上限（分） = min(max(estimated_minutes * 3, 15), 180)
```

| 目安時間 | 実測採用上限 |
|---:|---:|
| 4分 | 15分 |
| 10分 | 30分 |
| 30分 | 90分 |
| 60分 | 180分 |
| 119分 | 180分 |

2〜5分程度の提案へ「目安×3」だけを適用すると、少し準備をしただけで実測値が捨てられるため、最低15分の許容上限を設ける。一方、寝落ちや数日後の完了による極端値を防ぐため、絶対上限は180分とする。

表示する実測分数は秒から最も近い整数へ丸め、1分未満は1分とする。上限判定は丸め前の経過時間で行う。

## 日付跨ぎの扱い

「開始日と終了日が違う」だけではフォールバックしない。

例えば23:55に開始して翌00:05に完了した10分間は、正当な実測値である。寝落ちや翌日以降の完了は、多くの場合、目安との倍率または180分上限で除外できる。

0以下の経過時間は、端末時刻の手動変更などで発生する不正値として目安へフォールバックする。

## 保存形式

- `SuggestionRecord` に nullable な `started_at` / `completed_at` を追加する
- `created_at` は履歴の作成時刻と並び順のために残す
- 新規doneレコードでは `created_at` と `completed_at` に同じ終了時刻を使う
- 新規の開始・終了時刻はUTCのISO 8601文字列で保存する
- records のスキーマをversion 2へ更新する
- versionなし・version 1は開始・終了時刻なしとして読み込む
- 任意の日時フィールドだけが壊れていてもレコード全体を捨てず、目安時間へフォールバックする
- 未知のフィールドは従来どおり無視する

開始・終了時刻は shared_preferences にだけ保存し、既存の履歴削除で一緒に削除する。外部送信や新しい権限追加は行わない。

## 表示と集計

- 有効な実測値を使うdone履歴：`実測 N分`
- 実測できないdone履歴：`目安 N分`
- skipped履歴：`目安 N分`
- 合計時間：doneレコードごとに採用した時間を合計する
- サマリーには「実測を優先し、記録がない場合は目安で集計」していることを短く示す

値を2つ併記すると履歴一覧が読みにくくなるため、実際に集計へ使った値だけを表示する。`実測` / `目安` のラベルで根拠を明確にする。

## 完了時の確認を採用しない理由

完了モーダルでは既にフィードバックを選んで保存する。さらに時間の確認や編集を必須にすると、最も重要な完了操作の手数が増える。

まずは自動計測、異常値フォールバック、履歴上の根拠表示で信頼性を確保する。手動編集は、実測値への不満が利用確認で見つかった場合に別Issueで検討する。

## 中断機能との関係

Issue #137 の結論を、実測時間導入の前提にはしない。現時点では開始から完了までを連続した経過時間として測る。

将来、計測を止める中断を導入する場合は、実施中状態に累計中断時間を保存し、完了時の経過時間から差し引く。中断した提案の一覧や再開方法は、既存のスキップ復活フローとの関係を含めてIssue #137側で決める。

## 実装時の確認項目

- 正常な実測値と整数分への丸め
- 1分未満の実測値
- 0以下の経過時間
- 目安×3、最低15分、最大180分の境界
- 短時間の日付跨ぎ
- 開始・終了時刻の欠損、型不一致、日時パース失敗
- versionなし・version 1からversion 2への後方互換
- skipped履歴が実測時間を持たないこと
- スキップ履歴から復活した実施中の計測
- 履歴一覧の `実測` / `目安` 表示
- 実測と目安が混在する合計時間
- `flutter analyze`
- `flutter test`
