# 履歴絞り込みの検討結果

最終更新：2026年7月29日

関連Issue：

- 検討：[Issue #135](https://github.com/AltHiroaki/yorimitiBiyori/issues/135)
- 実装：[Issue #159](https://github.com/AltHiroaki/yorimitiBiyori/issues/159)
- 週間ダッシュボードの検討：[Issue #136](https://github.com/AltHiroaki/yorimitiBiyori/issues/136)

## 結論

履歴画面に、期間の `今週 / 全期間` と、ステータスの `すべて / 実施 / スキップ` を追加する。

期間はサマリーと一覧の両方へ適用し、ステータスは一覧だけへ適用する。サマリーでは、選択期間内の実施数、スキップ数、合計時間を常に比較できるようにする。

Issue #135は方針決定までを対象とし、実装、既存仕様書の更新、テスト追加はFeature Issue #159で行う。#159が完了するまでは、現在の履歴画面に絞り込みがあるものとして扱わない。

## 現行実装の確認

- 履歴は `created_at` の新しい順で1本のリストに表示される
- 実施・スキップは同じ一覧に混在し、各行のバッジで区別される
- 実施履歴は閲覧、スキップ履歴は復活フローを開く
- サマリーは全履歴の実施数、スキップ数、doneの合計時間を表示する
- 完了直後の履歴IDは `highlightedRecordId` で受け取り、対象行を強調する
- 履歴タブへ切り替わった時点で保存データを再読み込みする

ステータスごとにタップ時の動作は異なるが、履歴という同じ情報集合であり、別画面へ分割しなくても行のバッジと絞り込みで識別できる。

## 決定事項

| 論点 | 決定 |
|---|---|
| 期間 | `今週 / 全期間` の2つ |
| 1か月 | 今回は追加しない |
| 今週の定義 | 端末ローカル時刻の月曜日00:00から現在まで |
| 期間UI | 2択のセグメントコントロール |
| ステータス | `すべて / 実施 / スキップ` |
| ステータスUI | 単一選択のフィルタチップ |
| サマリー | 期間には連動し、ステータスには連動しない |
| 初期状態 | `今週 / すべて` |
| 状態保存 | shared_preferencesへ保存しない |
| タブ切替 | HistoryPageのStateがある間は選択を維持する |
| 完了直後 | 新しい履歴が必ず見える条件へ補正してハイライトする |

1か月は、今週と全期間の中間として必要になる利用実績がまだないため追加しない。選択肢を先に増やさず、長期履歴が増えて必要性が確認できたときに追加する。

## UI構成

上から次の順に配置する。

1. 期間：`今週 / 全期間`
2. サマリー：`実施 / スキップ / 合計時間`
3. ステータス：`すべて / 実施 / スキップ`
4. 履歴一覧

期間は画面全体の集計対象を切り替えるためセグメントコントロールとする。ステータスは同じ一覧の候補を減らす操作なのでフィルタチップとする。

実施・スキップを入れ子のタブや別画面へ分けると、3タブのボトムナビゲーションの中に別のタブ階層が増える。履歴の比較と切替にはフィルタで十分なため、別画面にはしない。

セクション見出しで実施・スキップを並べる案は、件数そのものを減らせず、時系列も分断するため採用しない。

## 今週の定義

「今週」は、レコードの `created_at` が次の範囲に入るものとする。

```text
端末ローカル時刻の月曜日 00:00 <= created_at <= 現在時刻
```

「直近7日」ではなくカレンダー週を採用する。今週の活動量として理解しやすく、Issue #136で曜日別集計を追加する場合も同じ月曜日始まりの期間判定を再利用できるためである。

UI表記は曖昧な `1週間` ではなく `今週` とする。未来時刻のレコードは、端末時刻の変更などで存在しても今週へ含めない。

## 絞り込みと集計

処理順は次のとおり。

1. 保存済みの全レコードを読み込む
2. 選択期間に含まれるレコードを抽出する
3. 期間内レコードからサマリーを集計する
4. 期間内レコードへステータスフィルタを適用する
5. 一覧を `created_at` の新しい順に並べる

サマリーはステータスフィルタへ連動させない。例えばスキップ履歴だけを見ている場合も、その期間の実施数とスキップ数を比較できる。

ステータスへ連動させると、`実施` 選択時にスキップ数が常に0となり、3分割サマリーの比較価値が失われるため採用しない。

## フィルタ状態

- 初期状態は `今週 / すべて`
- shared_preferencesへは保存しない
- 通常のタブ切替と履歴再読み込みでは、現在の選択を維持する
- アプリ再起動やHistoryPageの再生成時は初期状態へ戻す

絞り込みは閲覧時の一時的な状態であり、ユーザー設定ではない。保存データとスキーマを増やさず、毎回予測できる初期状態から始める。

## 完了直後のハイライト

完了フローから新しい `highlightedRecordId` を受け取った場合は、対象レコードがフィルタで隠れないようにする。

- ステータスを `すべて` にする
- 対象が今週なら `今週` にする
- 対象が今週に含まれない場合は `全期間` にする
- 絞り込み後の一覧で既存のハイライトアニメーションを実行する

通常のタブ切替や再読み込みでは選択をリセットしない。補正するのは、新しいハイライト対象が渡されたときだけとする。

## 空状態

保存済み履歴そのものが0件の場合は、現在の全体空状態を使う。

- `まだ履歴はありません`
- `提案を見てみる`

履歴は存在するが絞り込み結果が0件の場合は、全体空状態と区別する。

| 条件 | 見出し | 主な導線 |
|---|---|---|
| 今週・すべてで0件 | `今週の履歴はありません` | `全期間を見る` |
| ステータス指定で0件 | `この条件の履歴はありません` | `すべて表示` |

絞り込み結果が0件でも、サマリーは選択期間の値を表示し続ける。ステータスだけで0件の場合、期間内の他ステータスの件数を確認できる。

## 共通ロジック

期間とステータスの判定はHistoryPageへ直接書かず、records feature配下の純粋関数として実装する。

- 現在時刻は `DateTime now` として引数で受ける
- 引数のレコード一覧を変更しない
- 月曜日境界、月跨ぎ、年跨ぎ、未来時刻を単体テストする
- Issue #136の週間集計でも同じ期間判定を使う

## 実測時間との関係

Issue #156が先に実装された場合、期間内レコードを実測優先対応済みのサマリー関数へ渡す。履歴絞り込み側で、合計時間や異常値フォールバックを再実装しない。

#156と#159は `record_summary.dart` と `history_page.dart` が競合する可能性がある。先にマージされた変更を取り込んでから実装し、期間抽出と時間算出の責務を分ける。
