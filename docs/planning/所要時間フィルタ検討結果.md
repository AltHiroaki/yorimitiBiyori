# 所要時間フィルタ検討結果

最終更新：2026年7月28日

関連Issue：

- 検討：[Issue #133](https://github.com/AltHiroaki/yorimitiBiyori/issues/133)
- 実装：[Issue #154](https://github.com/AltHiroaki/yorimitiBiyori/issues/154)

## 結論

提案設定に、任意の「時間の上限」フィルタを導入する。

カテゴリとカテゴリ別詳細設定の二段階方式は維持し、その条件で作った候補集合に対する補助的な安全上限として扱う。旧仕様の `selected_minutes` のような必須の共通条件や、通知から都度選ぶ時間条件は復活させない。

Issue #133 は方針決定までを対象とし、実装、既存仕様書の更新、テスト追加は Feature Issue #154 で行う。#154 が完了するまでは、現在のアプリに時間上限フィルタがあるものとして扱わない。

## 判断の根拠

2026年7月28日時点の `assets/data/suggestions/*.json` を集計した結果は次のとおり。

| カテゴリ | 全件 | 中央値 | 15分以下 | 30分以下 | 60分以下 |
|---|---:|---:|---:|---:|---:|
| 音楽 | 402 | 4分 | 402 | 402 | 402 |
| 料理 | 399 | 18分 | 159 | 395 | 399 |
| 読書 | 334 | 15分 | 181 | 334 | 334 |
| 映画 | 232 | 119分 | 3 | 3 | 3 |
| 散歩 | 3 | 15分 | 2 | 3 | 3 |

短い空き時間でも長時間の映画が抽選され得る現状は、アプリの「空いた時間に、小さなよりみちを。」という体験と合わない。一方で、時間上限を必須にすると候補の幅を狭め、初期設定の負担も増えるため、初期値は「指定なし」とする。

映画は15分、30分、60分のいずれでも候補が3件しかない。また、料理は15分以下にすると、ジャンルと調理法の56通りの組み合わせのうち30通りで候補が0件になる。したがって、映画だけを例外処理するのではなく、実際の絞り込み結果に基づく候補不足の案内が必要である。

## 決定事項

| 論点 | 決定 |
|---|---|
| 導入するか | 導入する |
| 絞り込み方法 | 上限のみの単一選択 |
| 選択肢 | `指定なし / 〜15分 / 〜30分 / 〜60分` |
| 適用範囲 | 全カテゴリ共通。カテゴリ別の時間設定にはしない |
| 初期値 | `指定なし` |
| 配置 | 提案設定画面のカテゴリ別詳細設定より下に、独立した横断設定として置く |
| 保存 | `user_settings` の `max_estimated_minutes` に保存する |
| 映画の扱い | 自動除外しない。時間上限の選択時に候補が少ない旨を案内する |
| 候補が0件のとき | 時間上限が原因かを判定し、時間上限またはカテゴリ・詳細設定の見直しを案内する |
| 条件の自動緩和 | 時間上限とカテゴリは自動で緩和しない |

60分は現行データでは30分に対して料理4件を追加するだけだが、1時間以内という理解しやすい区切りであり、料理を全件候補に戻しつつ長時間の映画を除外できるため残す。120分は短い空き時間という目的から外れるため、今回の選択肢には含めない。

## 旧仕様との整理

廃止済みの「共通の使える時間」と、今回の「時間の上限」は次の点で異なる。

| 旧仕様 | 今回の方針 |
|---|---|
| 提案条件の中心となる共通条件 | 二段階設定を補助する任意の安全上限 |
| 分数の指定を前提とする | `指定なし` が初期値 |
| 通知アクションから15/30/60分を選ぶ | 通知アクションは追加しない |
| 時間・予算・距離を並べる | 時間上限だけを追加し、予算・距離は復活させない |

通知文言は引き続き分数を名指ししない。通知を開いた後は、保存済みのカテゴリ、詳細設定、時間上限を使って提案する。

## 実装契約

### 保存

- `max_estimated_minutes` は nullable な整数とし、許容値は `15 / 30 / 60` のみとする
- キー欠落、`null`、型不一致、許容外の値は `指定なし` として読む
- `user_settings` のスキーマバージョンを2へ更新する
- versionなし、version 1のデータは `max_estimated_minutes = null` として移行する

### 絞り込み

次の順序で候補を絞り込む。

1. 選択カテゴリ
2. カテゴリ別の詳細設定
3. `estimated_minutes <= max_estimated_minutes`
4. 直近提案の除外

候補不足時に直近除外を一時的に緩和しても、時間上限は維持する。時間上限やカテゴリを暗黙に解除して提案してはならない。

### 表示

- 提案設定では「時間の上限」として単一選択を表示する
- 提案条件カードには、指定時だけ `時間の上限：〜N分` を表示する
- 時間上限の適用前には候補があり、適用後に0件になった場合は、時間条件が原因だと分かる文言を表示する
- 映画を選択中に15分、30分、60分のいずれかを指定した場合は、現行データでは候補が少ない旨を設定画面で案内する

## 実装時の確認項目

- モデルのJSON往復、旧バージョン移行、不正値フォールバック
- カテゴリ、詳細設定、時間上限を組み合わせたフィルタ
- 直近除外を緩和しても時間上限を超えないこと
- 設定画面の単一選択、保存、復元
- 条件カードの指定あり・指定なし表示
- 時間上限が原因の0件表示
- 映画の候補不足案内
- `flutter analyze`
- `flutter test`
