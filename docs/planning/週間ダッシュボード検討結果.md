## 結論

提案タブへ新しい週間ダッシュボードは追加しない。

履歴タブにある `実施 / スキップ / 分` のサマリーカードを実績表示として使い、上部の `今週 / 全期間` でサマリーと履歴一覧の集計対象を同時に切り替える。

- `今週`：端末ローカル時刻の月曜日 00:00 から現在まで
- `全期間`：保存済みの全履歴
- 初期値：`今週`
- ステータスの `すべて / 実施 / スキップ`：一覧だけを絞り込み、サマリーには適用しない

## 理由

提案タブは、表示中の提案へ集中する画面として維持する。週間グラフやカテゴリ内訳を追加すると画面の役割が増え、提案カードへ到達するまでの情報量も増える。

履歴タブには既に期間選択、3指標のサマリー、履歴一覧が同じ順序で並んでいる。別のダッシュボードを増やさず、期間選択をサマリーと一覧へ共通適用する方が、同じ期間の実績と内訳を一貫して確認できる。

## 集計の流れ

1. 保存済みの全履歴を読み込む
2. `今週 / 全期間` で対象レコードを抽出する
3. 対象レコードから実施数、スキップ数、合計分を集計する
4. 同じ対象レコードへステータスフィルタを適用して一覧を表示する

ステータスフィルタをサマリーへ適用すると、実施だけを表示したときにスキップ数が常に 0 となり、期間内の比較ができなくなる。そのため、サマリーは期間だけに連動させる。

## 現行実装

Issue #159で、履歴タブの期間選択と期間連動サマリーは実装済み。

- `history_filter.dart` がカレンダー週と全期間の抽出を担当する
- `history_page.dart` が期間内レコードを `summarizeRecords` へ渡す
- 期間を切り替えるとサマリーと一覧を同じ対象範囲で再計算する
- 期間とステータスの選択は、HistoryPageのStateがある間だけ保持する

Issue #136では重複実装を行わず、実施数、スキップ数、合計分の3指標すべてが期間切替へ連動することをWidgetテストで明示的に保証する。

## 今回追加しないもの

- 提案タブの週間実績表示
- 曜日別グラフ
- カテゴリ別内訳
- 連続日数
- 新しい保存データや依存パッケージ

これらは利用実績を確認して必要性が明確になった場合に、別Issueで検討する。

## 確認項目

- 初期状態のサマリーが今週の履歴だけを集計する
- 全期間へ切り替えると過去の履歴を含めて再集計する
- 実施数、スキップ数、合計分がすべて期間に連動する
- ステータスフィルタを変更してもサマリーは変わらない
